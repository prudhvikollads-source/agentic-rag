Agentic RAG

A corrective / self-RAG system over a bundled 12-document corpus: retrieve → grade → rewrite if weak → generate with citations → verify groundedness → abstain when the evidence is not there. Fully offline: pure-Python BM25 + a deterministic extractive model. This page is a recorded run — no live backend.

Q: How do I pay less money for computers?

A: Cloud bills are dominated by a small number of services, so cost optimisation starts by tagging every resource with an owner and a project. [10-cloud-cost-optimization] Without tags, a bill can be reported only as a single total, and no team can be held accountable for its share. [10-cloud-cost-optimization] Reserved capacity is the largest single saving lever for steady workloads. [10-cloud-cost-optimization] The trade-off is flexibility: the commitment is paid for whether or not the capacity is actually used, so reservations should cover only the stable baseline of a workload, never its peaks. [10-cloud-cost-optimization] Monitoring data typically shows many virtual machines running at a small fraction of their provisioned CPU, and moving each workload to the smallest instance size that still meets its performance target cuts its hourly cost directly. Recorded run 2 — a direct answer

Q: What does a data lakehouse add on top of a data lake?

A: A data lakehouse combines the low-cost object storage of a data lake with the management features of a data warehouse. [02-data-lakehouse] Files remain in open formats such as Parquet, but a table format layer adds structure and guarantees on top of those files. [02-data-lakehouse] The table format layer adds transactions to the lake. [02-data-lakehouse] The same layer provides schema enforcement, which rejects writes whose columns do not match the declared table schema, and schema evolution, which allows columns to be added in a controlled way. [02-data-lakehouse] Unlike a traditional warehouse, a lakehouse keeps data in open file formats, so multiple engines — a SQL engine, a Spark job, or a machine learning training run — can read the same tables without exporting copies between systems. [02-data-lakehouse]
